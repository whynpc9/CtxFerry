# CtxFerry Desktop · MyGo Native UI 设计规格

Native UI 修订版 · 2026-11-19 · 适用 #28–#32，覆盖首次接入和桌面侧验收。文中的界面、服务名、示例设备状态和验收目标均为设计；八张 PNG 使用合成数据，描绘相关核心能力交付后的目标界面。#28 首个只读切片的范围见第 7 节。

**产品定位**　给同时使用多台设备的开发者一个本地管理窗口。在该窗口里，用户能回答三个问题：哪个项目在这台机器上使用哪份配置、一次同步或任务因何停下、下一步操作会改变哪台设备上的什么数据。CLI 和桌面共用一套操作语义；每个页面都能沿着具体对象回到证据和修复入口。

**确定路线**　MyGo v0.10.0 Native UI。窗口以 WindowOptions.Content 承载 Go 视图。视图操作通过 Go 调用共享应用核心；SQLite 和 Git 仍由核心管理，后台同步由用户服务承担。库的控件在系统窗口中由 MyGo 绘制，文件对话框、菜单、输入法和辅助技术与平台集成。

| 导航层 | 入口和位置 | 用户到这里做什么 |
| --- | --- | --- |

| 管理 | 设备与资源、凭据绑定、Skills、产物 | 对照设备观察、解释凭据条件、预览文件变更、定位运行结果。可从项目带入筛选。 |

| 首次使用 | 未初始化落到欢迎页；已初始化但未绑定显示下一步；已配置进入总览 | 新建本地工作区或加入已有工作区。允许只使用本地功能。 |

**上下文定位。** 窗口顶栏显示 workspace 与对象路径，侧栏底部固定本机身份，侧栏主区选择工作面，内容标题上方显示对象路径。Project、checkout、Profile 只在影响结果的页面出现，在编辑和探测动作旁重复显示写入或执行目标。设备筛选改变所查看的记录；本机身份固定。工作区内用稳定 ID 导航，标题和别名仅作展示。点击总览冲突数字直达过滤后的队列；只有一个时可直达详情。返回列表恢复筛选、滚动和焦点。

**三级披露。** 总览显示数量、设备和最需处理的对象；列表显示对象、状态、来源与观察时间；详情再展示证据、受影响范围与动作。未初始化、空列表、过滤无结果、核心暂未提供、请求失败分别处理。只有查询成功且确实无记录才显示“0”。未订阅项目进入“选择项目”，零冲突显示“当前没有冲突”，筛选无结果提供“清除筛选”。

## 3 · 页面与核心旅程

### 3.1 总览 → 同步 → 冲突

总览首屏固定展示设备、已绑定项目数、待发布数、冲突数和上次确认同步时间。列表上方的工作区提示给出项目、冲突记录、双方来源和“比较版本”入口。切换选中项目只更新右侧检查器。其下列项目和本机 Git、Infisical、后台服务三个独立状态。设备离线时保留本地可读内容和最后观察时间。没有待办时收起提示，使项目列表自然上移。

同步页展示私有仓库、分支、最后确认的 head 和时间、待处理记录、冲突、历史体积与备份。首次启用需验证仓库身份与私有性，展示将进入 Git 的记录和对象、大小、排除项以及共享正文的明文边界，再确认该次预览。仓库不能确认私有时停止发布；共享关系牵涉 local-only 时列出阻塞的记录和关系，回到项目调整。刷新只重读本地视图。“检查远端”发起联网读取。待发布数量旁的“预览发布…”针对当前可发布记录，先列出可发布变更和本次排除的冲突，再由用户确认发布。[同步发布确认态](states/02-sync-preview.png) 展示两条纳入记录、一条排除记录、目标分支和正文的明文边界。

**示例操作。** 用户从 mac-mini 上的提醒进入“测试环境说明”，逐字段比较共同基线、本机、远端。每版显示设备、revision、时间，突出变化；缺失基线、删除与空文本分别标记。删除与修改相冲突时，按钮直写“保留删除”或“保留此版本”。记录过长可只看变化，原始字段值允许换行。敏感引用只展示允许展示的元数据。

初次打开不预选结果。图 03 展示用户已选“采用本机”后的预览。Context 文档可编辑新版本；当前核心只支持为 context 提交替换内容，其他类型仅提供实际支持的选项。涉及凭据引用、资源用途、执行参数、敏感级别或 Skill pin 时必须显式选择。提交携带本次查看的 conflict token。过期提示“比较后记录已变化，请载入最新版本”，返回比较且保留可复核的草稿。成功显示“已生成本机修订，等待发布”；只有核心确认远端 head 后才显示已同步。[现有 Resolve 行为](https://github.com/whynpc9/CtxFerry/blob/4380e35f1310b65098f81c73204b3a017b05ce84/internal/app/sync_conflicts.go)

**队列与备份。** 单条记录冲突时，独立记录继续处理。背景服务未安装显示“仅在前台或调用时同步”；已安装须结合实际运行状态。备份详情列生成时间、纳入范围、排除项、引用对象与校验结果，默认排除 local-only。全工作区恢复前显示目标、恢复范围、新 epoch 和其他设备尚未发布的修改怎样保留，要求单独确认。相关能力未交付时提供状态说明。关闭窗口后已安装的服务继续运行。

### 3.2 项目 → 配置 → 恢复继承

列表区分已订阅项目和已绑定本机 checkout。一个项目可关联多个仓库、子目录和 worktree。有多个 checkout 时显式选择，若识别歧义则列出候选。详情展示 checkout 和当前 Profile，下设 Context、资源、Tasks、配置、Skills、产物。点开 Context 显示来源、修订、新鲜度及披露规则；文档作为文本或经限制的 Markdown 呈现。Task 详情显示用途、输入、槽位及本机执行定义的信任状态；敏感执行字段变更后，先在本机预览差异再启用。

字段行展示**当前值、来源、要编辑的层、改动影响范围**。顺序为全局 → 项目 → 显式 Profile → 设备 → checkout。写共享层显示将影响哪些继承者，写设备或 checkout 显示本机范围；较高层仍有覆盖时同时列出“保存到该层的值”和“当前生效值”。不适用或路径缺失，在字段旁解释具体原因。选择 Profile 是本机上下文操作。

**示例操作。** 用户打开 dbark 的 development Profile。项目层的 timeoutSeconds 为 60，本机设备覆盖为 90，checkout 未设置。选中设备层的“恢复为继承”后先预览 90 秒 → 60 秒，确认时只移除该字段在该层的值。重新查询核心，来源变为“项目”。其他设备的值保持各自的解析结果。验证可用同一 checkout 的 context explain 对照来源。支持字段、值域和路径规则取自核心。秘密映射和命令定义走专门编辑流程。[已合并配置契约](https://github.com/whynpc9/CtxFerry/blob/f412994bb7f2e770bdb1fcd8eda006ff2c150c82/docs/context.md#ordinary-configuration-and-profiles)

### 3.3 凭据绑定 → 槽位诊断 → 本机认证

入口先选 Project、Profile、Task、槽位。列表显示用途、资源、要求类型、选中的 SecretBinding 别名、provider 及定位元数据。支持从现有兼容绑定中显式选取，或新建引用后映射。保存前列出变更的范围及受影响 Task；已有绑定被多个项目复用时明确显示。每个动作使用核心兼容性检查。绑定记录共享，认证属于当前 Device；Windows 与 WSL 各有状态。

**示例操作。** dbark 集成检查已绑定 test-db-reader，Infisical 会话需登录。界面依次列出“槽位已绑定 / 本机需登录 / 条目可读性未知 / 上次 TCP 可达 / 任务未运行”。打开受控的本机认证入口，返回后重新检查该设备；条目可读性只在显式检查后更新。provider 能提供条目管理链接时由系统浏览器打开。页面不提供明文、复制值、通用 JSON 展开器或 vault 搜索。缺失映射直接定位对应槽位。权限不足和找不到条目按核心可安全区分的程度展示。Infisical 先接；Bitwarden 等适配器交付后复用同一交互。

### 3.4 设备与资源 → 核对意图 → 显式探测

左侧看执行环境或按物理主机分组，右侧看资源、用途、业务 stage、非秘密端点、访问路线及适用条件。Windows 和 WSL 即使同机，仍分别列出 Device ID、路径和观察。每条 Observation 附设备、工具、时间、范围；没有远端观察时显示未知。选择资源不触发网络探测。“在本机探测”明确目标、设备和探测类型，结果追加到观察列表。TCP 可达、provider 认证和 Task 测试通过分别有各自的证据。失败时保留配置意图和其他设备的历史。

### 3.5 Skills → 预览 → 安装 / 更新 / 回滚

索引按来源和已选 pin 组织，详情分为“共享安装意图”“本机安装结果”。按 Agent（Codex、Claude Code）和 cwd 查看适用目标；实际发现顺序只有经该 adapter 验证才显示，未知则展示候选位置。来源 commit、包摘要、已安装文件摘要和本机 ownership 分列。界面示例采用受管复制，可选择经验证能用的软链。

示例中选择候选 pin 只预览。通过计划校验后，确认页分别列出共享 pin 的新值和 mac-mini 的目标文件；其他设备接收版本意图后独立应用。

选候选 pin → 核心生成 plan → 逐项展示新增、替换、删除、已有本地修改、外来文件 → 查看 diff → 确认写入范围并 apply。存在本地修改时展示本机目标路径。用户在外部处理文件后重新扫描，核心重新核对所有目标并报告时间和阻塞数。只有当前计划通过核查才可继续。[重新扫描回执](states/07-skills-rescanned.png)执行中返回页面仍从核心读取操作状态；中断后显示恢复结果。回滚显示前一已装版本和目标文件，完成后重新核查安装。共享 pin 与 mac-mini 的安装结果各自呈现。作为用户安装的 ctxferry Skill 是 #22；开发 Desktop 时使用的 MyGo 工具 Skill 归开发环境管理。

### 3.6 产物 → 按项目与运行追溯

列表可按项目、run、来源设备、缓存状态过滤，行中展示名称、实际完成范围、大小、位置和摘要。区分本机已有、远端对象可取、仅元数据、本地文件缺失及校验失败。下载后由核心验摘要才变为“本机已缓存”。仅元数据详情说明超额或保留原地的原因，以及已知来源设备；若无可取 payload，隐藏下载动作。来源设备的绝对路径只有在适用的本机视图中显示。配额、缓存和 Git 历史增长警示取自核心；搜索或打开目录记录不触发大文件传输。

### 3.7 首次接入、加入与恢复

| 场景 | 操作顺序 | 暂停与恢复 |
| --- | --- | --- |
| 首台设备 | 初始化本地工作区 → 选择目录并预览识别结果 → 绑定 checkout → 预览可选 Skill 与受管引导块 → 可选 Infisical 认证 → 选择本机私人说明并分类 → 可选私有远端及首次上传预览 → doctor 能力清单 | 可跳过可选步骤，显示“继续在本机使用”。每步完成由 Go 保存，与 CLI 共用进度。 |
| 第二台设备 | 输入私有 remote → Git 身份与隐私核对 → 拉取并校验 → 选项目订阅 → 绑定本机 checkout / Profile → 按需安装 Skills 和认证 provider | 中断回到最后已确认步骤。认证 Git 失败时保留本地选择；无 provider 认证仍可看已同步的资料。 |
| 私人文档 / env | 明确选择文件 → 在本机预览字段名、分类和发现类型 → 分别设置存储范围与 Agent 披露 → 确认。env 走专门的 provider 导入，逐项核对目标映射。 | 取消导入不发布。导入失败显示哪个映射需处理，恢复由核心记录决定。秘密文件只作数据解析。 |

首台设备示例依次给出[欢迎页](states/setup-welcome.png)、[目录绑定预览](states/setup-checkout.png)和[跳过可选配置后的本地就绪回执](states/setup-local-ready.png)。第二台设备示例给出[私有仓库核验](states/setup-private-remote.png)和[中断恢复](states/setup-resume.png)。

发布与拉取确认均展示 Git 主机、所有者、仓库名和分支。加入前说明共享记录与 Git 历史将被拉到本机，校验后选择的项目订阅控制本机索引、展示、Skill 投影和缓存。接入步骤栏标出当前位置；可返回选择工作区来源，或保存已确认进度后退出。绑定前可在目录信息内选择配置方案。恢复页可稍后继续；重新选择来源前先核对已保存的进度。目录绑定以“绑定此目录”提交，回执列出已保存的目录和配置方案。步骤栏标明已完成、当前、已跳过与未开始。

新设备约五分钟可用是 PRD 在 Git/provider 账户已就绪时的体验目标。未来测量从首次打开到能在本机找到项目与上下文，另外记录外部认证与依赖安装耗时。

## 4 · 共用状态、反馈和视觉系统

| 当核心报告 | 用户看到 | 可执行动作或恢复 |
| --- | --- | --- |
| synced / pending / conflict | 已确认的 head 与时间 / 本机有 N 项待发布 / 需选择的记录 | 查看队列或三方比较，完成后重新读取核心 |
| offline / 未观察 / stale | 离线及最后已知时间 / 尚未检查 / 观察已过期 | 本地继续阅读或编辑；用户明确要求时重试联网 |
| auth-required / unlock-required | 指出 Git 或指定 provider、设备和最近检查时间 | 进入相应的本机认证或解锁流程，再检查 |
| incomplete / missing-branch | 远端目录不完整或分支缺失，本机修改已保留 | 查看已配置的仓库与分支，修复后重新核验 |
| unsupported-schema / history-rewritten | 哪个操作被暂停、现有本地资料可做什么 | 显示兼容性或恢复详情，由用户选择下一步 |
| project-unbound / profile-required | 候选项目或可选 Profile，附当前 checkout | 显式绑定或选择，再返回原任务 |
| binding-missing / conflict / incompatible | 具体 Task、槽位及不相容的类型或用途 | 展示映射编辑器或冲突详情 |
| secret-unavailable / resource-unreachable / platform-unsupported | 条目、探测或平台条件分别显示原因 | 跳转 provider / 路线 / 适用性说明 |
| execution-definition-changed | 此设备需重新批准，逐项列出执行字段变化 | 在本机核对并显式启用该版本 |
| 部分失败、重复提交、窗口中断 | 保留已成功的板块和草稿；写入中的按钮防重复。若提交结果未知，显示“正在核对结果” | 从核心重读 revision 或操作记录，判定是否已完成后再提供重试 |

每条反馈回答“哪个对象、在哪台机器、何时观察、接下来能做什么”。写入有本机完成、待发布和远端已确认三个反馈点。切换页面不清除操作回执；返回编辑器时，如果底层版本改变，提示用户比较而后再次提交。错误正文使用稳定错误码配人能读的说明；诊断详情只含允许字段。

**窗口设计。** 采用系统标题栏、可拖动分隔条和可用键盘遍历的工具栏。左栏选择七个工作区入口，中央是所选对象的表格或工作面；检查器展示选中对象的来源、影响范围和下一步操作。返回时恢复列表选择和滚动位置。冲突比较需要最大的可用宽度，进入后以比较工作面替换列表和检查器。设计图使用合成数据，呈现窗口内容区。

| 元素 | 原生交互规范 |
| --- | --- |
| 导航 | ui.Sidebar 按稳定 ID 选择对象，ui.Router 保存窗口历史，工具栏返回/前进与平台菜单连接同一动作。分隔条可用鼠标拖动或以方向键移动。 |
| 表格和检查器 | ui.Table 保留列标题、选中行与可见行渲染；对象状态以稳定 ID 随刷新保留。选择行只更新检查器，双击或 Enter 打开详情。上下文菜单复用工具栏动作；关键动作始终有键盘入口。 |
| 视觉与密度 | 使用 MyGo 主题的背景、表面、文字、选中和边框色。正文约 14–16 DIP，字段名称 12–14 DIP，主标题 22–26 DIP；路径、head、revision 用等宽字或等宽数字。图中文字和标签区分待处理、未知与成功。亮暗主题与高对比偏好分别检查。 |
| 窗口变化 | 宽窗口允许侧栏、主区、检查器并排。窄窗口先收起检查器，详情作为可返回的下一层；三版本比较按字段纵向排列并保留各版来源。收窄和放大字体时仍可到达确认动作。 |
| 键盘与焦点 | 工具栏内方向键移动，Tab 转入列表；列表用方向键选行。Esc 关闭检查器浮层或取消对话框，焦点回到触发项。中文 IME 组词期间 Enter 仅确认输入。操作完成后播报状态，列表刷新不抢焦点。 |
| 可访问性 | 使用控件原有角色和值，图标动作另设 Label；错误字段关联说明，差异附“新增 / 移除”。正常文本对比目标 4.5:1，焦点及控件 3:1。分别用 VoiceOver、Narrator 或 NVDA、Orca 验证所支持平台。 |

## 5 · 原生技术选型

| 层 | 决定与实现边界 |
| --- | --- |
| 窗口与入口 | 独立桌面入口创建 mygo.NewWindow，设置 StateKey 和 Content: ui.View(...)。CLI 单独构建，检查其依赖图及无图形环境下的运行。桌面资源与依赖版本随桌面包锁定。[窗口 API](https://github.com/egoist/mygo/blob/v0.10.0/docs/ui/windows.md) |
| 组件 | 首版选 MyGo 自带 Sidebar、Toolbar、Split、Table、Form、Dialog、Segmented、文本与输入控件。项目层只组合“范围与来源”“操作回执”“逐字段三版比较”等具有 CtxFerry 语义的视图。 |
| 状态与导航 | 每个窗口维护 Go 视图状态，包括 ui.Router、稳定对象 ID、ui.ListState、筛选、草稿、查询代次与分栏宽度。ui.Element 仅在当次构建有效。渲染函数只消费快照，业务写入由显式动作触发。[视图生命周期](https://github.com/egoist/mygo/blob/v0.10.0/docs/ui/views.md) |
| 读取与并发 | 慢速 Git、provider 或文件读取在后台调用核心。丢弃过期查询结果；在 UI 主线程提交结果并请求重绘。关闭窗口取消属于窗口的查询；已受理的同步或文件操作按核心实际回执恢复。 |
| 应用与存储 | 视图事件 → Go 控制器 → internal/app 用例 → SQLite、Git 或对应 adapter → 类型明确的视图状态。原生菜单、快捷键、主按钮走同一动作。UI 只接收允许显示的字段；凭据页面的状态结构不含值。 |
| 平台 | macOS、Windows 和 Linux 各保留系统窗口行为。MyGo 原生渲染器在三平台分别支持 Metal、Direct3D、OpenGL 等路径；字体回退、缩放、输入法、读屏、菜单与对话框分别实测。[渲染器](https://github.com/egoist/mygo/blob/v0.10.0/docs/ui/rendering.md) |

**页面到控件和用例的映射**

| 工作面 | 原生控件组合 | 操作合同 |
| --- | --- | --- |
| 总览 | Sidebar、Toolbar、项目表格、本机状态摘要 | 本地快照分项载入，显示 pending、冲突和最后确认 head，点选进入对应对象。 |
| 同步 | 记录表格、类型筛选、检查器、确认对话框 | SyncStatus 与发布预览分开调用；选择队列记录只读详情。分支、明文边界、备份范围在对应写入动作前显示。 |
| 冲突 | 三列字段比较、选择器、结果预览、确认按钮 | 项目组合三版本及来源。editor.DiffView 自带的是**两个文本**的差异视图，可用于基线与所选版本的展开比较。三方解决仍由核心 Conflict / Resolve 及 token 校验承担。[DiffView](https://github.com/egoist/mygo/blob/v0.10.0/docs/ui/diff-viewer.md) |
| 项目 | checkout 选择器、分段导航、字段表格、来源检查器 | 读 #5 explain，编辑或恢复指定层后重读；不允许改变层时显示原因。 |
| 凭据 | 槽位表、诊断清单、受限元数据和本机认证动作 | 展示绑定、认证、可读取、资源可达、任务结果五项状态，显式映射后从核心重读。 |
| 设备与资源 | 分组的设备列表、资源表、观察详情、显式探测按钮 | 已合并的 #6 提供本机 TCP 观察；远端无证据时显示未知。 |
| Skills | 来源与安装记录、变更文件表、两版本差异视图 | 先 plan，选择文件读变更后再 apply 或 rollback。使用只读 diff 查看将写入的内容，本地编辑保留冲突标记。 |
| 产物 | 项目/run 筛选器、文件表、对象检查器 | 区分本机缓存、可下载、仅元数据。对象校验通过后才更新本机可用性。 |

**状态的来源。** Overview 聚合彼此独立的查询，以局部错误保留其余面板。Git 可达、仓库确认为私有、Git 身份已认证各有独立来源。若核心只返回可达性，页面仅报告可达，把认证标为“未知”。provider 登录同样不推断某个条目可读。队列明细、历史体积或逐项目计数若缺少投影，先使用核心确知的总数；示例中的明细、备份和认证均描述目标状态。

**内容边界。** 文档、同步记录和差异作为数据绘制。外部 provider 管理链接通过系统浏览器打开。Go 控制器核对链接目的、作用域和操作前置条件，诊断与剪贴板只接触允许披露的字段。

**生态取舍。** [Onevra](https://github.com/oneo-me/onevra) 和 [Lobe MyGo](https://github.com/lobehub/lobe-mygo) 都是原生 UI 候选。#28 最需要的侧栏、分栏、可选行表格和无障碍支持在固定版已有，首个切片直接使用官方控件。若后续引入具体组件，先用同一份长表格、中文输入和读屏场景验证兼容性，再锁定版本与许可。MySkills 的来源与安装区分、Knack 的按 Agent/cwd 诊断、kura 的文件 diff 与回滚仍用于交互设计。

**旧规格对齐。** 用户已确定 Native UI。历史 [PRD](https://github.com/whynpc9/CtxFerry/blob/4380e35f1310b65098f81c73204b3a017b05ce84/PRD.md)、线上总规格 #1 和 #28 中的 WebView + React 条款属于旧路线。本地 PRD 已随本设计修正。线上工单待同步的验收措辞为：① 主窗口使用 MyGo Native UI Go 视图，直接调用共享应用核心；② 外链交系统浏览器，外部内容仅按数据展示；③ 开发构建启动后通过原生可访问性节点切换总览和同步，验证本机快照、焦点与结果；④ 关闭窗口后后台同步独立运行，CLI 在无 GUI 的机器上工作。

## 6 · 验收任务与证据

| 任务 | 可观察的通过条件 |
| --- | --- |
| 首次使用和离线 | 无 provider 登录也能初始化并绑定；在 CLI 与 GUI 间切换后从同一步继续。断网仍能读取本机 Context，面板显示上次观察时间。 |
| 两种状态并存 | 有一条冲突、两条待发布时，总览的两组计数分别准确，点击后能定位对应对象。关闭窗口后用独立用户服务验证另一台设备收到新 revision。 |
| 三方冲突 | 用键盘比较并选定；没有选择时不能提交；若另一客户端已解决则收到过期反馈。成功后 CLI 读到新 revision，另一端在发布成功后收到同一修订。 |
| 配置继承 | 以 #5 字段完成图 04 的 90 → 60；context explain 显示项目来源；另一个设备及其他字段的覆盖各自保留。 |
| 凭据与资源 | 对已绑定但未认证的槽位独立显示五项条件；Windows / WSL 分列；探测前后保留原配置。用带已知合成值的 fake 检查允许展示的 DTO、页面及日志，真实 Infisical 另验本机认证与受控读取。 |
| Skills 与产物 | 制造一处本地编辑，更新前可发现并检查 diff；应用失败保留旧版本，回滚可复查。超额产物显示仅元数据，下载可用对象时验证摘要。 |
| 可用性走查 | 让试用者从总览定位冲突、恢复配置继承、解释凭据失败原因。分别记录路径、是否选错设备/层、能否解释操作结果，再改导航或文案。全程键盘、中文 IME、系统缩放、长路径和长列表均可操作。 |
