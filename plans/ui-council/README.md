## 从首稿到定稿

- **第 1–4 轮** 将所选项目与检查器对应，把三方版本、设备来源和修订并排呈现。总览的同步确认时间与 Git、Infisical 的认证时间分开。
- **第 5–8 轮** 将发布范围、配置写入层、本地修改阻塞和设备探测目的地放到对应操作附近。新增发布确认态，显示纳入、排除、目标分支和 Git 明文边界。
- **第 9–12 轮** 补齐接入与中断恢复状态，发布预览可核对具体变更，Skills 重扫可从本地修改跟踪到解除阻塞。冲突页按选择、结果全文、本机提交排列。
- **第 13–15 轮** 拉近重新扫描与恢复说明，明确预览会影响共享 pin 及本机文件。待发布数旁可以进入发布预览；冲突入口直接说明将筛选队列。目录绑定支持选择配置方案，就绪回执集中展示已保存信息。

执行沿用了独立评委和多轮复审方法，并按本项目要求固定了模型、七项评分、冻结及停止规则。操作详见 Skill。[上游 Council 固定版本](https://github.com/t3dotgg/tstack/blob/11e37a74d0a6868c121cd0910ab2b3bd9873b92a/skills/council/SKILL.md)

## 复现和遗留意见

在单独的临时目录解压出图模块，使用兼容 Go 1.27.3 的工具链运行 `go run -mod=mod . png`。此次用 Go 1.27.4、MyGo v0.10.0 在 macOS arm64 从便携模块重新生成全部 15 张 PNG；每张均与冻结包逐字节一致。仓库内的图稿、规格与归档文件清单也已核对。

以下意见随定稿保留，供开发验收使用。

- **Skills 文件核验。** 两票指出复扫回执缺少可逐项核对的摘要。预览覆盖前需能区分来源 commit、候选包摘要、已安装文件摘要和本机文件的管理归属。
- **列表追溯。** 队列的工作区确认时间无法替代逐条来源与观察时间。产物较多时，需要从列表对照完成范围、内容位置和校验摘要。
- **辨识与对比。** Astra 报告配置选择器的边线与面板约为 1.31∶1。Gemini 指出冲突新增片段的边线形似插入光标、筛选栏只读值的基线与控件有偏差、接入步骤小号状态字偏淡。开发时应复核控件 3∶1 及正文 4.5∶1 的规格目标。
- **实机范围。** 本次覆盖静态图稿。窗口缩放、键盘焦点、中文 IME、读屏、暗色、高对比主题和真实同步、认证、写入回执均待开发后另验。
